## 1. 개요

메인 › 월정액구매 진입 시 **가입가능 월정액 상품을 자동 조회** → 상품 선택 → 결제·할인 수단 선택 → 구매 요청(IF-EPS-001) 을 수행한다.

### 1.1 1차 확정 범위

| 구분 | 1차 (구현) | 추후 |
|---|---|---|
| [A] 상품 조회 | 전체 (검색조건 상품유형 · 상품명, 진입 시 자동 조회, 목록, 페이지, 구매 확인 팝업) | — |
| [C] 약정 선택 | 전체 (무약정 + 약정기간 옵션, 가격, 약정필수 규칙) | — |
| [C] 결제 수단 | **청구서** 만 활성 (단건구매와 동일) | 청구서 외 6개 |
| [C] 할인 수단 | 쿠폰 · T멤버십 **2개만 표시, 비활성** | 쿠폰번호 · T멤버십 정보 조회 후 활성 |
| 구매 요청 | IF-EPS-001 | — |
| [D] 구매완료 | 전체 (단건구매와 동일) | — |

## 2. 화면 흐름

```
메인 ─▶ [A] 상품 조회 (진입 시 자동 조회) ─(행 클릭 → 구매 확인 팝업)─▶ [C] 결제·할인 ─(N원 결제)─▶ [D] 구매완료
             ▲                                                          │ 구매취소                  │ 홈으로 → 메인
             └──────────── 조회조건 · 페이지 유지 + 자동 조회 ◀──────────┴───────────────────────────┘ 구매 계속하기
```

- 단건구매와의 차이: **Step 1(상품 유형 · 언어 · 화질) 없음**, 결제·할인 화면에 **약정 선택** 추가, [A] 진입 시 **자동 조회**, 검색조건 **상품유형(쿼리 분리) + 상품명**
- 공통 동작 "조회 화면으로 복귀", 구매 확인 팝업, [D] 구매완료: 단건구매 spec 과 동일

## 3. 요구사항

### R1. [A] 상품 조회
- R1.1 가입가능 월정액 상품을 Oracle 에서 조회 (`query_productList_{유형}.sql`)
- R1.2 검색 조건 2개
  - **상품유형** (선택, 기본 `전체`) — WHERE 조건이 아니라 **선택값에 따라 실행할 Query 파일을 바꾼다** (쿼리 분리)

| 상품유형 선택 | 실행 Query | 조회 대상 (`GUBUN`) |
|---|---|---|
| 전체 | `query_productList_all.sql` | CUG · OMNI 제외 전 유형 |
| VOD | `query_productList_vod.sql` | VOD (VOD PPM / 복합 VOD PPM) |
| CMP | `query_productList_cmp.sql` | CMP (PPM커머스, PRD_TYP_CD 36) |
| YTP | `query_productList_ytp.sql` | YTP |
| DNP | `query_productList_dnp.sql` | DNP |
| VAS | `query_productList_vas.sql` | VAS |
| IPTV | `query_productList_iptv.sql` | IPTV |

  - 선택 표시명은 `GUBUN` 코드 그대로 (목록 `구분` 컬럼과 동일)
  - **OMNI(OMNIPACK, PRD_TYP_CD 38)는 조회하지 않는다** — 원본의 CMP/OMNI 공용 블록을 `PRD_TYP_CD = '36'` 으로 한정
  - 원본의 `PERD`(PRD_TYP_CD 32)는 원본 조건상 조회되지 않으므로 선택지에 없음
  - **상품명** (텍스트) — NULL 또는 빈 문자열이면 전체. 대소문자 구분 없음 (`UPPER` 비교). 모든 유형 Query 에 동일하게 적용
  - 조합: 전체 / 유형별 전체 / 상품명 검색(전체 또는 특정 유형)
- R1.3 조회에 **설정 › 서비스관리번호** 사용 (원본 Query 의 하드코딩 값 → 바인드 변수 `:svcMgmtNo`)
  - 주민법인일련번호(`CTZ_CORP_SER_NUM`)는 서비스관리번호로 조회: `SELECT CTZ_CORP_SER_NUM FROM IESM_CUST_SVC WHERE ID_CUST_SVC = :svcMgmtNo` (Query 내 서브쿼리)
  - **`GUBUN = 'CUG'` 는 조회하지 않는다** (Query 에서 해당 구간 제거)
- R1.4 **메인에서 진입 시 자동 조회** (상품명 빈 값 = 전체)
- R1.5 결과 목록 컬럼 (Query 결과 전체)

| 컬럼 | 필드 | 비고 |
|---|---|---|
| 구분 | `GUBUN` | VOD / CMP / YTP / DNP / VAS / IPTV (CUG · OMNI 제외) |
| 상품ID | `ID_PRODUCT` | IF-EPS-001 Path `{상품가격ID}` |
| 상품명 | `NM_PRODUCT` | |
| 패키지ID | `ID_PACKAGE` | |
| 상위상품ID | `ID_PRODUCT_PAR` | |
| PPM유형 | `TP_PPM` | |
| 가격 | `AMT_PRICE` | **부가세 포함** (Query 에서 ×1.1), 우측 정렬 + `원` |
| 무료가입기간 | `PPM_FREE_JOIN_PERD_CD` | 코드 그대로 표시 |
| 약정필수 | `AGMT_MNDT_YN` | Y / N |

- R1.6 정렬: `NM_PRODUCT` → `ID_PRODUCT` (페이지 고정용). 원본의 CUG 우선 정렬은 CUG 제외로 불필요
- R1.7 페이지 처리 · 결과 없음 표시 · 조회 실패 표시 · 행 클릭 확인 팝업(`[상품명] 을 구매하겠습니까?`): 단건구매 R1.6 · R1.7 · R1.7a · R1.8 과 동일
  - 약정 옵션 조회(`query_agreementList.sql`) 실패 시: 약정 영역에 `조회에 실패했습니다. ({오류 메시지})` 표시, `[N원 결제]` 비활성
- R1.8 `[구매취소]` / `[구매 계속하기]` 복귀: 조회조건 · 페이지 유지 + 자동 조회 (단건구매 2. 공통 동작)

### R2. [C] 결제·할인 수단 선택
- R2.1 레이아웃은 단건구매 Step 2 와 동일하되 **스텝 칩 없음**, 상단 제목 = 상품명, 안내문구 `결제 및 할인 수단을 선택해 주세요.`
- R2.1a **약정 선택** (라디오, 단일 선택) — 결제 수단 왼쪽 첫 번째 컬럼
  - 옵션: `무약정` / `{N}개월` (약정기간 개월 수), 행마다 **가격** 표시
  - **무약정은 약정 Query 로 조회하지 않는다** (약정기간 0, 가격 = 상품 금액이므로). 약정필수 N 상품이면 화면에서 `무약정` 옵션을 직접 생성 (가격 = 목록 `AMT_PRICE`, `prdAgmtId` = null)
  - 목록에서 **약정필수(`AGMT_MNDT_YN`) = Y** 인 상품은 **`무약정` 옵션 없음**
  - 기본 선택: 첫 번째 옵션 (무약정이 있으면 무약정)
  - 선택 변경 시 결제 금액 패널 · `[N원 결제]` 버튼 금액 즉시 반영
  - 옵션 구성
    | 옵션 | 표시 | 가격 | `prdAgmtId` |
    |---|---|---|---|
    | 무약정 (약정필수 N 일 때만, **조회 없이 화면에서 생성**) | `무약정` | 목록의 `AMT_PRICE` | null |
    | 약정기간 (`query_agreementList.sql`, `:prdPrcId` = 선택 행 `ID_PRODUCT`) | `{PER_MM_CNTR}개월` | `AMT_SALE` (부가세 포함) | `PRD_AGMT_ID` |
  - 약정 옵션 순서: 무약정 → 개월 수 오름차순 (Query 정렬)
  - 약정필수 Y 인데 약정 Query 결과가 0건이면: `선택 가능한 약정이 없습니다` 표시, `[N원 결제]` 비활성
  - 참고(표시하지 않음): `CNTR_NAME`, `AMT_DSC`, `RT_DSC` 수신
- R2.2 결제 수단: 단건구매와 동일 7개 (청구서, 신용카드, 휴대폰, 카카오페이, 네이버페이, PAYCO, SK pay) — 1차는 **청구서만 활성**
- R2.3 할인 수단: **쿠폰, T멤버십 2개만** — 1차는 **둘 다 비활성**(☒) 표시
- R2.4 결제 금액 패널: 상품 금액 / 할인 금액 / 부가세 / 구매 금액 — **가격은 부가세 포함으로 표시** (목록 `AMT_PRICE`, 약정 `AMT_SALE` 모두 부가세 포함). 상품 금액 = 선택한 약정 옵션 가격, 부가세 = `포함`, 구매 금액 = 상품 금액 - 할인 금액
- R2.5 하단 액션바: `상품 선택 내역` = 상품명 | 선택한 약정 (`무약정` / `{N}개월`), 버튼 `[구매취소]` `[N원 결제]` (Step 1 이 없으므로 `[이전]` 없음)
- R2.6 `[구매취소]` → [A] 복귀 (R1.8), `[N원 결제]` → 구매 요청 → [D]

### R3. 구매 요청
- R3.1 IF-EPS-001 — Header · Body 매핑은 단건구매 spec 4. 설계 › IF-EPS-001 요청 매핑 과 동일 (STB ID 는 `020_singlePurchase/design/query_stbId.sql` 로 요청 직전 조회)
- R3.2 차이점

| 항목 | 값 |
|---|---|
| Path `{상품가격ID}` | `ID_PRODUCT` (채널 상품(`GUBUN = IPTV`)은 CHNL_PRD_ID 가 들어있음 — 규격상 동일 위치 사용) |
| `useBcash` | `false` (월정액 할인 수단에 B캐시 없음) |
| `useCoupon` / `couponNo` | `false` / null — 추후 |
| `useUniverseDiscount` 등 T멤버십 필드 | `false` — 추후 |
| `prdAgmtId` | 선택한 약정 옵션의 `PRD_AGMT_ID` (채널팩은 `CHNL_PRD_AGMT_ID` 가 같은 컬럼으로 조회됨), **무약정 = null** |

- R3.3 Response `purchaseType` 은 `VODPPM` / `IPTVPPM` 으로 수신됨 (표시하지 않음)
- R3.4 `contentId` 미전송, STB ID 0건 · 조회 실패 처리: 단건구매 R5.1 과 동일

### R4. [D] 구매완료
- 단건구매 R5 와 동일 (성공 / 에러 메시지, `[홈으로]` · `[구매 계속하기]`)
