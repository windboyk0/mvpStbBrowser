## 1. 개요

메인 › 단건구매 진입 후 **구매가능 상품 조회 → 상품 유형 선택(Step 1) → 결제·할인 수단 선택(Step 2) → 구매 요청** 을 수행한다.
기존에 Postman으로 수기 입력하던 구매 요청 값을 화면 선택으로 대체하는 것이 목적이다.

### 1.1 1차 확정 범위

| 구분 | 1차 (구현) | 추후 |
|---|---|---|
| [A] 상품 조회 | 전체 (검색조건 2개, 목록, 페이지, 구매 확인 팝업) | 해상도·시청가능기간 실데이터 (Query 수신 후) |
| [B] Step 1 | 선택한 상품 1건 표시 (4. 설계 › Step 1 1차 데이터) | 옵션(유형·언어·화질) 여러 개 선택 |
| [C] Step 2 결제 수단 | **청구서** 만 활성 | 신용카드 · 휴대폰 · 간편결제 (선행 절차 필요) |
| [C] Step 2 할인 수단 | **B캐시** 만 활성 (체크 시 `useBcash: true`). 설명 영역은 **`{N}P 차감` 만** 표시 (잔액 미조회, N = 상품 금액 + 부가세) | 쿠폰(쿠폰번호 조회) · OK캐쉬백 · T멤버십 · TV포인트, 잔액 표시 |
| 구매 요청 | **IF-EPS-001** (청구서 포함) | — |
| [D] 구매완료 | 전체 | — |

- 추후 항목의 행·버튼은 화면에 표시하되 **비활성**(☒, 클릭 불가)으로 둔다 — 참고 화면의 T멤버십 · TV포인트 표현과 동일
- `선택한 결제수단을 다음 번에도 사용` 체크박스: 1차는 **표시만, 동작 없음** (체크 상태 저장 · 반영 안 함)
- 4. 설계의 Step 1 / Step 2 레이아웃 도식과 R2 · R3 의 항목 설명은 **참고 화면 기준 전체 모습**이다. 1차에 실제로 활성화되는 범위는 이 표(1.1)를 따른다

             ▲                                        │ 구매취소       │ 이전 → [B] / 구매취소          │ 홈으로 → 메인

| C | Step 2 결제·할인 수단 선택 | `PPV-Purchase_Step2*.png` + 사용자 지시 (구매취소) | 설계 |
| D | 구매완료 | 사용자 지시 (성공/에러 메시지, 홈으로 · 구매 계속하기) | 설계 |

### 공통 동작 — "조회 화면으로 복귀"
`[구매취소]` (Step 1 · Step 2), `[구매 계속하기]` (구매완료) 는 동일하게 동작한다.
- [A] 상품 조회로 이동하면서 **직전 조회조건(상품유형, 상품명)을 유지**하고 **자동으로 재조회**한다
- 페이지: **직전에 보던 페이지 유지**

## 3. 요구사항

### R0. 진입 조건
- R0.1 진입 시 `singlePurchase:checkSettings` 로 필수 설정(`serverUrl`, `svcMgmtNo`, `dbConnectString`, `dbUser`, `dbPasswordEnc`) 확인
- R0.2 하나라도 없으면 팝업 `설정을 먼저 입력해 주세요.` — `[취소]` → 메인 (`app:navigate` `main`), `[설정으로]` → `app:navigate` `settings`

### R1. [A] 상품 조회
- R1.1 구매가능한 단건 상품을 Oracle에서 조회하여 목록으로 보여주고, 행을 선택해 구매를 진행한다 (`query_productList.sql`)
- R1.2 검색 조건 2개

| 조건 | 입력 | 값 | Query 반영 |
|---|---|---|---|
| 상품유형 | 선택 (기본 `전체`) | 전체 / VOD PPV / VOD PPS / VOD PPP / VOD Commerce | 전체: `PRD_TYP_CD IN ('10','20','41','42')` / 그 외: 해당 코드 1개 |
| 상품명 | 텍스트 | NULL 또는 빈 문자열이면 전체 | 값 있을 때만 `PRD_NM LIKE '%{상품명}%'` |

- R1.3 상품유형 코드 ↔ 표시명: `10` VOD PPV, `20` VOD PPS, `41` VOD PPP, `42` VOD Commerce
- R1.4 조합 모두 조회 가능: 전체 검색(유형 전체 + 상품명 없음) / 유형별 전체(상품명 없음) / 상품명 검색(유형 전체 또는 특정 유형)
- R1.5 결과 목록 컬럼: 상품가격ID(`PRD_PRC_ID`), 상품명(`PRD_NM`), 판매가(`SALE_PRC`), 상품유형(`PRD_TYP_CD` → 표시명), **해상도(`RESOLUTION`)**, **시청가능기간(`VIEW_PERIOD`)**
  - 해상도 · 시청가능기간은 해당 필드가 포함된 Query 수신 전까지 **빈 값**으로 조회·표시 (Query에서 `NULL AS ...`, 화면은 빈 칸)
- R1.6 페이지 처리: **페이지당 10건**, 페이지 번호 / 이전 / 다음. 최소 창 크기(1280×800)에서 세로 스크롤 없이 표시
- R1.7 결과 없음: 목록 영역에 `조회된 상품이 없습니다` 표시
- R1.7a 조회 실패 (DB 접속 · Query 오류): 목록 영역에 `조회에 실패했습니다. ({오류 메시지})` 표시 (`danger`), 건수 · 페이지 숨김. `[검색]` 으로 재시도
- R1.8 행 클릭 → 확인 팝업 `[상품명] 을 구매하겠습니까?` 표시
  - `[확인]` → 선택한 상품으로 Step 1 이동 / `[취소]` → 팝업 닫고 목록 유지
- R1.9 정렬: **상품유형코드(`PRD_TYP_CD`) → 상품가격ID(`PRD_PRC_ID`)** 순, 오름차순
- R1.10 메인에서 진입 시 **자동 조회하지 않는다.** 최초 목록 영역에는 `[검색]을 눌러 상품을 조회하세요` 안내만 표시하고, 건수·페이지는 숨긴다
- R1.11 `[구매취소]` / `[구매 계속하기]` 로 복귀한 경우에는 직전 조회조건으로 **자동 조회** (2. 공통 동작)

### R2. [B] Step 1 상품 유형 선택
- R2.1 상단: 스텝 칩(`Step 1` 활성 / `Step 2`), 콘텐츠명, 안내문구 `구매하실 상품 유형을 선택해 주세요.`
- R2.2 3개 컬럼으로 선택: **상품 유형** / **언어** / **화질**
  - 상품 유형: 행마다 유형명(예: 소장(단편)), 설명(예: B tv 해지 전까지 무제한), 할인 배지(예: `100% 할인 적용`), 가격
  - 언어: 행마다 언어명(예: 한글자막)
  - 화질: 라디오 + 화질명(HD / UHD / HDR), 할인 배지, 가격
- R2.3 각 컬럼 단일 선택. 선택된 항목은 `focus` 색 텍스트로 표시
- R2.4 하단 액션바: `상품 선택 내역` (선택한 유형 | 언어 | 화질 | 부가문구), 안내문구 `결제 후에는 취소 및 환불이 되지 않으며 콘텐츠 시청 시 광고가 포함될 수 있습니다.`, 버튼 `[구매취소]` `[다음]`
- R2.5 `[다음]` → Step 2, `[구매취소]` → [A] 조회조건 유지 + 자동 조회 (2. 공통 동작)
- R2.6 옵션 간 종속(유형 → 언어 → 화질), 부가문구(`mobile B tv에서 시청 가능`) 노출 조건은 **Query 수신 후 확정**

### R3. [C] Step 2 결제·할인 수단 선택
- R3.1 상단: 스텝 칩(`Step 2` 활성), 콘텐츠명, 안내문구 `결제 및 할인 수단을 선택해 주세요.`
- R3.2 **결제 수단** (라디오, 단일 선택, 목록 세로 스크롤): 청구서, 신용카드, 휴대폰, 카카오페이, 네이버페이, PAYCO, SK pay
- R3.3 **할인 수단** (체크박스) — 제목 옆 안내 `결제 수단 변경 시, 할인 수단이 변경될 수 있습니다.` (아래 표는 참고 화면 기준 전체 모습 — 1차 활성 범위는 1.1)

| 할인 수단 | 설명 영역 | 금액 | 부가 요소 |
|---|---|---|---|
| 쿠폰 | 적용 쿠폰명 (예: DK-단건) | 할인액 | 적용 시 말풍선 `자동 적용` |
| B캐시 | `잔액 N P / N P 차감` | 할인액 | `[충전]` 버튼 또는 말풍선 `충전 혜택 받기` |
| OK 캐쉬백 | `잔액 N P / N P 차감` | 할인액 | — |
| T멤버십 | `T멤버십 번호 등록` | 할인액 | 참고 화면에서 비활성(☒) |
| TV포인트 | `포인트 조회` | 할인액 | 참고 화면에서 비활성(☒) |

- R3.4 **결제 금액** 패널: 상품 금액 / 할인 금액 / 부가세 / 구매 금액(밑줄 강조), 하단 체크박스 `선택한 결제수단을 다음 번에도 사용` (1차 동작 없음)
- R3.5 하단 액션바: 상품 선택 내역(Step 1과 동일), 버튼 `[이전]` `[구매취소]` `[N원 결제]` (구매 금액 실시간 반영)
- R3.6 `[이전]` → Step 1 (선택 유지), `[구매취소]` → [A] 조회조건 유지 + 자동 조회 (2. 공통 동작), `[N원 결제]` → 구매 요청 → [D] 구매완료
- R3.7 금액 계산 규칙 — 4. 설계 › 금액 계산 참고
- R3.8 각 할인 수단의 잔액·쿠폰 목록 조회 방법, 결제 수단별 가능한 할인 수단 규칙은 **추후** (1차는 B캐시만 사용하므로 해당 없음)

### R4. 구매 요청
- R4.1 모든 결제 수단(청구서 포함)은 **IF-EPS-001** 로 요청한다 (4. 설계 › IF-EPS-001 요청 매핑)
- R4.2 1차는 청구서 + (B캐시 선택 시) B캐시 로 요청 (1.1 1차 확정 범위)
- R4.3 모든 연동은 main 프로세스에서 수행한다 (CLAUDE.md › Architecture)

### R5. [D] 구매완료
- R5.1 구매 요청 결과를 **성공 메시지 또는 에러 메시지**로 표시한다
  - 성공 (`result = "0000"`): `구매가 완료되었습니다.`
  - 에러 (그 외 `result`, 통신 오류 포함): 응답 `reason` 메시지 (`\\n` 은 줄바꿈 처리). 통신 오류로 응답이 없으면 `구매 요청에 실패했습니다.`
  - 요청 전 STB ID 조회(`query_stbId.sql`) 결과 0건: 요청하지 않고 `서비스관리번호에 해당하는 STB가 없습니다.` / 조회 실패: `조회에 실패했습니다. ({오류 메시지})`
- R5.2 버튼 2개: `[홈으로]` → 메인, `[구매 계속하기]` → [A] 조회조건 유지 + 자동 조회 (2. 공통 동작)
- R5.3 참고(표시하지 않음): 성공 시 `senderPurchaseNo`, `purchaseType`, `productName` 수신 / 실패 시 `needsCancel`, `purchaseList.purchaseInfo[]` 수신

- VAS(TVApp) 상품 구매 (`inApp`), 분할 결제, 약정 할인, PLCC 카드, PPV+커머스(DIS 인증)
